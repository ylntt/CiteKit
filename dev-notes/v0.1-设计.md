## 验收标准

换台机器 clone → 装依赖 → 放文档 → 跑两条命令 → 得到**带文件名出处的答案**。

## 对 `rag_test.py` 的审查（v0.1 必修）

1. **`format_docs` 丢掉文件名**：只拼 `page_content`，`metadata["source"]` 被扔 → 模型看不到文件名 → 出处不可溯源。
   修：`f"[来源: {d.metadata.get('source')}]\n{d.page_content}"`
2. **变量被复用**：`docs` 先装加载结果、后装检索结果，同名两义；加增量逻辑后必炸。
3. **`sources` 是 `str`**：应改成 `list[str]`（或 `file` + `quote` 结构）才算"带出处"。
4. **`chunks[:1]`**：起手只放 1 块，应为 `[:10]`（DashScope 单次上限 10 条）。
5. **脚本式顶层执行 + 每次全量重建**：切块与 embedding 每次运行都重做（慢且花钱）→ 拆模块 + 索引落盘。

次要：注释掉的手工分批代码（`vectors` 那段）可删，FAISS 分批已够用。

## v0.1 关键 API 实测输出（离线探针，未调用任何 API）

探针做的事：`TextLoader(..., encoding="utf-8-sig")` → 切块 → 假 embeddings（继承 `Embeddings`）建 FAISS → `save_local` / `load_local` → 检索一次。原样输出：

```
documents: 1 | chunks: 11
chunk[0] metadata: {'source': 'C:\\Users\\ASUS\\AppData\\Roaming\\JetBrains\\PyCharm2026.1\\scratches\\test\\CiteKit\\docs\\示例-组内职责说明.md'}
chunk[0] first char: '#'
isinstance(emb, Embeddings): True
saved files: ['index.faiss', 'index.pkl']
load_local(no flag): FAILED -> ValueError | The de-serialization relies loading a pickle file. Pickle files can be modified  ...
load_local(flag=True): OK, docs = 11
similarity_search(k=2): 2 hits | first: ## 三、常见流程
hit metadata: {}
as_retriever(k=4).invoke: 4 docs
load_local signature: (folder_path: 'str', embeddings: 'Embeddings', index_name: 'str' = 'index', *, allow_dangerous_deserialization: 'bool' = False, **kwargs: 'Any') -> 'FAISS'
save_local signature: (self, folder_path: 'str', index_name: 'str' = 'index') -> 'None'
```

结论：

- 示例文档在 `chunk_size=100 / chunk_overlap=20` 下切成 **11 块**；每块保留 `metadata["source"]`（完整文件路径） —— 这就是"出处"能标到文件名的依据。
- **`load_local` 必须显式传 `allow_dangerous_deserialization=True`**，否则抛 `ValueError`：docstore 是 pickle，从本地文件加载属于反序列化，需要明确同意。（v0.1 第 2 步必踩，先探明。）
- 注意：**metadata 来自你交给库的 `Document` 对象**。探针用 `FAISS.from_texts`（纯文本）建库，所以命中项 metadata 是 `{}`；正式流程必须用 `FAISS.from_documents(chunks, embeddings)`（chunks 来自 `split_documents`），metadata 才会跟着文档进库，检索结果才能反查文件名。
- `save_local(".index")` 产出两个文件：`index.faiss` + `index.pkl`，缺一不可；`.index/` 已在 `.gitignore`。
- **BOM 坑（实测）**：带 UTF-8 BOM 的文档用 `encoding="utf-8"` 读，BOM 会变成正文第一个字符 `\ufeff` 混进第一块；用 `utf-8-sig` 读则自动吃掉（实测 `utf-8` → `'\ufeff'`，`utf-8-sig` → `'#'`）。ingest 读文档统一用 `utf-8-sig`。
- 教训（探针自身踩的）：拿普通对象冒充 embeddings 时，FAISS 会走已弃用的"传函数"路径，`similarity_search` 报 `TypeError: 'FakeEmb' object is not callable`。自定义 embedding 必须继承 `langchain_core.embeddings.Embeddings`。

## 两条路径规则（先定死，免得后面踩）

1. **运行方式**：`python src/ingest.py` / `python src/ask.py`（在 PyCharm 里直接 Run 文件也一样）。因此 `ingest.py` / `ask.py` 内部用**同目录写法** `from kb import ...` —— 按路径运行脚本时，`sys.path[0]` 就是脚本所在目录。
2. **路径一律锚定 `__file__`，不要依赖 cwd**：

```python
PROJECT_ROOT = Path(__file__).resolve().parent.parent   # src/ 的上一级 = 项目根
DOCS_DIR = PROJECT_ROOT / "docs"
INDEX_DIR = PROJECT_ROOT / ".index"
```

原因：PyCharm 直接 Run 时工作目录是**脚本所在目录**（`src/`）。若用相对路径 `.index`，从 PyCharm 跑索引会落进 `src/.index`，从命令行跑又落在项目根 —— 同一个项目长出两套索引，极难排查。
